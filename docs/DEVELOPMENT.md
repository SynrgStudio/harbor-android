# Development

Native Android app (Kotlin + Jetpack Compose): TMDB metadata, streams from Stremio addons and torrent streaming with librqbit.

Two Gradle modules:

- `core/`: plain Kotlin on the JVM, no Android. Stremio (account, addons, sync, "watched" marks, stream rules), metadata (TMDB API and addon, Wikidata), progress, settings, lists and stats, backups, the episode calendar, the subtitle parser, downloads and automatic downloads, the torrent engine's HTTP side, and "Play on a TV" (`CastManager`, `LanServer`, `Dlna`). Sources in `core/src/main/kotlin/com/synrg/harbor/`.
- `app/`: the Android app on top of it: screens, player, notifications and services, widget, updater, and the Android pieces the core asks for (`AndroidTorrentBackend` starts librqbit through JNI, `AndroidDownloadHost` with `DownloadService`, `GoogleCast` for Chromecasts, `AndroidNetworkMonitor`). Sources in `app/src/main/java/com/synrg/harbor/`.

Both use the same packages, so paths below like `stremio/StremioSync.kt` are relative to one of those folders.

## Commands (PowerShell, from the repo root)

- `.\scripts\build-native.ps1` builds the torrent engine (`native/`, Rust + librqbit) for arm64 and x86_64 into `app/src/main/jniLibs` (not in git: run it on a fresh checkout or after touching `native/`).
- `.\scripts\emulator.ps1 [-Window]` starts the project AVD (`.tools/avd`, serial `emulator-5590`, headless by default). Start it in the foreground: if a background job launches it, the emulator dies when that job ends. It uses `-Gpu host`: with `swiftshader_indirect`, qemu crashes during the Baseline Profile run.
- `.\scripts\run.ps1 [-Release] [-Serial <ip:port>] [-NoBuild]` builds, installs the APK for the device's ABI and opens the app. With `-Release` it also applies and compiles the Baseline Profile (for a sideloaded app, Android would only do that while the phone is idle and charging).
- `.\scripts\baseline-profile.ps1` regenerates the Baseline Profile on the emulator (it sets `ANDROID_SERIAL` and never runs on a phone) into `app/src/release/generated/baselineProfiles`, which is committed. Regenerate it when screens or flows change. It doubles as a smoke test: if the release build doesn't start, it fails here.
- `bash scripts/jank.sh <serial>` measures jank (gfxinfo) over a scripted scroll of Home, with the phone unlocked and a release build.
- Phone over wireless debugging: `adb mdns services` shows the IP and ports; pair with `adb pair <ip:port> <code>`.
- `.\scripts\release.ps1 -NotesFile notes.md` publishes a GitHub release: it builds signed APKs, checks they aren't signed with the debug key, creates the `v<versionName>` tag and uploads `Harbor-<version>-<abi>.apk`. Bump `versionCode`/`versionName` and commit first.
- In-app updater (`update/Updater.kt`): reads GitHub's `releases/latest`, downloads the APK for the device's ABI, checks the SHA-256 GitHub reports and installs it with PackageInstaller. To test it, build an "old" copy with `.\gradlew.bat :app:assembleRelease '-Pharbor.versionCode=5' '-Pharbor.versionName=0.4.0'` (in PowerShell, `-P` arguments with a dot need quotes or they get split) and install it with `adb install -r -d`. `BuildConfig.SELF_UPDATE` turns it off for a store build.
- `.\gradlew.bat :core:test` runs the unit tests (`core/src/test`): Stremio's "watched" format against stremio-core's own examples, the subtitle parser, and the LAN server and DLNA against a fake renderer.
- No network or mobile data on the emulator: `adb shell svc wifi disable` leaves only the (metered) cellular network; add `svc data disable` for no internet at all.
- Open the app the way notifications and shortcuts do: `adb shell am start -n com.synrg.harbor/.MainActivity -a com.synrg.harbor.OPEN --es type tv --ei id 456 --ei season 38` (also `.RESUME --es key movie:1726` and `.DOWNLOADS`). `MainActivity` is `singleTop` and each window has its own `links`, not a global one: a `stremio://` link opens another window, which used to swallow them.
- Run the new-episode check by hand: `adb shell cmd jobscheduler run -f com.synrg.harbor 4201`. `am force-stop` wipes scheduled jobs (use `am kill` with the app in the background); `lastCheck` is in `files/episodes.json` (`run-as`).
- Check both languages: `adb shell cmd locale set-app-locales com.synrg.harbor --locales es` (or `en`; `--locales` empty goes back to the system language).
- Emulator screenshot from bash: `adb -s emulator-5590 exec-out screencap -p > shot.png` (in PowerShell 5.1 the redirect corrupts the PNG).
- Screenshots for the project page: `pm clear` the app for a clean English install, gesture navigation (`cmd overlay enable-exclusive --category com.android.internal.systemui.navbar.gestural`) and the status bar in demo mode (`settings put global sysui_demo_allowed 1`, then `am broadcast -a com.android.systemui.demo -e command clock -e hhmm 0941`, and the same for battery and network). For the player and streams, run `python scripts/demo-addon.py` and add `http://10.0.2.2:7311/manifest.json` in Settings: it serves the Blender open movies. Never use real stream addons or a real account in pictures.
- Series features on the emulator (next episode, skip intro, season and smart downloads): `python scripts/demo-addon.py --series tt0903747` answers every episode of that series with Tears of Steel. After changing the addon's manifest, clear the app's HTTP cache (`run-as com.synrg.harbor rm -rf cache/http`) and add it again: manifests are cached for 6 h.
- "Play on a TV" on the emulator: `python scripts/fake-tv.py` is a pretend DLNA TV on the PC; debug builds also look for it at `10.0.2.2:7320` (SSDP doesn't cross the emulator's network). It prints the commands it gets and fetches the video through `adb forward`. Chromecast needs a real device.
- SD card on the emulator: `adb shell sm set-virtual-disk true`, then `sm partition <disk from sm list-disks> public`.
- `web/` is the project page's corpus (facts, notes, screenshots and rules for harbor.synrgs.tech). When a release changes something the page says, update `web/` and add an entry to `web/CHANGELOG.md`; `web/rules.md` lists what the page must never say.

## Rules and gotchas

- `scripts/env.ps1` finds Java 17 (`~/.jdks`) and the Android SDK (`ANDROID_HOME`, `sdk.dir` in `local.properties`, or `%LOCALAPPDATA%\Android\Sdk`). `.ps1` files are UTF-8 **with BOM**, or PowerShell 5.1 mangles non-ASCII text.
- `local.properties` (gitignored) holds `sdk.dir` and `harbor.signing.*`, which points to the release keystore (kept outside the repo). Without it, release builds are signed with the debug key. Debug and release builds have different signatures, so one won't install over the other (uninstall first). The APK carries no API keys.
- The app ships no stream addons: it only seeds OpenSubtitles v3. Streams come with the Stremio account or from addons added by URL.
- Metadata (`tmdb/Metadata.kt`): without a key it comes from the TMDB addon (`TmdbAddon`, tmdb.elfhosted.com, with the `{"language":…}` config in the path); with a TMDB key in Settings, straight from the API (`TmdbApi`). Both use TMDB ids, so progress and the list don't depend on the mode. The addon's extras (`genre=…`, `search=…`) are escaped like `encodeURIComponent`: a raw `&` ("Sci-Fi & Fantasy") cuts the value.
- Stremio sync (`stremio/StremioSync.kt`): the `libraryItem` collection through api.strem.io's `datastoreGet`/`datastorePut`, keyed by IMDb id, with one playback state per title. It pulls when the app opens (at most once a minute) and pushes on pause, exit or finish, and when "My list" is toggled. Testing it writes to a real account.
- Manual "watched" marks (`stremio/WatchedMarks.kt`): in the app, a mark is progress at the end. In Stremio, `state.watched` is a bitfield `{anchorId}:{length}:{base64(zlib)}` over the video list sorted by season, episode and release date, taken from the account's first metadata addon (like Stremio does; almost always Cinemeta): `AddonRepository.seriesVideos` + `WatchedBitfield.kt`. If the order doesn't match Stremio's, marks land on the wrong episodes.
- Downloads (`downloads/`): one per video (id = progress key), run in `DownloadService` (a `dataSync` foreground service). Torrents download into librqbit's cache and, once complete, are moved (rename, same filesystem) to `filesDir/downloads`. `TorrentEngine.close` doesn't pause torrents "pinned" by a download. Subtitles are downloaded with the video, and the player uses them offline.
- Mobile data (`core/Network.kt`): on a metered network, torrents upload at 16 KiB/s (the lowest limit librqbit accepts without cutting requests) and the player asks before playing.
- Subtitle delay: `player/SubtitleDelay.kt` wraps the `TextRenderer` (it's `final`) and shifts its position. With a positive delay, a cue that already passed doesn't come back; the next one shows on time.
- librqbit 9.1: the `http-api` feature also needs `tracing-subscriber-utils`, and `Api::new` takes 3 arguments. Kotlin only calls `NativeEngine.start`; everything else goes through the HTTP API on 127.0.0.1 (`TorrentEngine.kt`).
- Many torrent results come without trackers: `DEFAULT_TRACKERS` in `TorrentEngine.kt` fills them in. Seed counts reported by addons can be stale; to test torrents, use a recent release.
- UI text: English in `res/values/strings_<area>.xml`, Spanish in `res/values-es/` and Brazilian Portuguese in `res/values-pt/`, with the same keys (shared ones in `strings_common.xml`; Portuguese plurals need `one`, `many` and `other`). Composables read them with `stringResource`/`pluralStringResource`; everything else in `app/` (view models, services, errors shown later) uses `core/Strings.kt`, and `Strings.locale` for dates and numbers (with `DateFormat.getBestDateTimePattern`). The `core` module has no resources: text it shows is a `CoreText` entry (`core/CoreStrings.kt`), read with `CoreStrings.get`; the app maps each entry to its resource in `CoreText.res` (`app/…/core/Strings.kt`), so a new entry needs a line there. Don't use the application context or `Locale.getDefault()` for UI text: after a per-app language switch they can keep the old language. First-run defaults for metadata language, region and subtitles follow the phone (`data/Settings.kt`); saved settings keep their value. `localeFilters` in `app/build.gradle.kts` and `res/xml/locales_config.xml` list the shipped languages: add a new one in both, plus its metadata language and genre names in `tmdb/Metadata.kt` (the TMDB addon filters by genre *name*).
- Measure performance with release builds only: Compose in debug is much slower.
- Text without an explicit color takes `LocalContentColor`, set in `HarborTheme` (there's no root `Surface`).
- No annotation-processing dependencies (no Room/Hilt/KSP): persistent state uses `core/JsonStore.kt`.
- Regexes run on Android's ICU engine, stricter than the JVM's that the unit tests use: escape a literal `}` (`\{[^}]*\}`), or the class fails to load on the phone only.
- Without a TMDB key, people and sagas come from Wikidata (`tmdb/Wikidata.kt`, SPARQL, cached 7 days): a person is found through the cast of the title they were opened from, to tell namesakes apart. Many well-known titles only have a `mul` label there: read `rdfs:label` for the language, `en` and `mul` (the label service skips them).
- "Play on a TV" (`cast/`): `LanServer` serves the video, proxied from the torrent engine or a link with headers, or a downloaded file, plus subtitles converted to VTT/SRT, on the Wi-Fi address under random tokens. Chromecast goes through Google's Cast library, created only when the TV list first opens (it has its own usage logging); 23.x needs compileSdk 37 and AGP 9.1, so it stays on 22.1.0. DLNA is SSDP + UPnP AVTransport in `cast/Dlna.kt` (tested against a fake renderer in `CastTest`). `CastService` keeps a wake lock while casting.
- Player sound (`player/SoundEffects.kt`): DynamicsProcessing on an audio session the app generates and gives ExoPlayer, so it exists before the first frame. The second subtitle is drawn by the app (`player/SubtitleFile.kt` reads SRT/VTT/ASS): Media3 shows one text track at a time.
- Automatic stream choices ("Play the best stream", season downloads, smart downloads) all go through `stremio/StreamRules.kt`.
- Downloads on an SD card (`Downloads.sdDir`) go to the app's folder on the card; torrents finish in the engine's cache on the phone and are copied there (a rename only works within one storage).
- Edit Gradle/TOML files without a BOM: PowerShell's `Set-Content -Encoding utf8` adds one and the version catalog stops parsing.
- `core/` has no Android SDK on its classpath, so an Android import there doesn't compile. What only a platform can give comes in from the app: interfaces (`TorrentBackend`, `DownloadHost`, `Chromecasts`, `NetworkMonitor`), constructor parameters (`CastManager`'s `holdMulticast` and `extraTv`, `Wikidata`'s `userAgent`, `Backup`'s `appVersion`) and `CoreStrings.source`. `AppGraph` wires them.
- The app's Compose compiler can't infer the stability of `core` classes (another module): models that reach the UI carry `@Immutable` (from `androidx.compose.runtime:runtime-annotation`, annotations only). Give a new one the same, or Compose compares it by identity and recomposes more. To check, add `composeCompiler { reportsDestination = layout.buildDirectory.dir("compose_reports") }` to `app/build.gradle.kts` and run `:app:compileReleaseKotlin --rerun`.
- Kotlin doesn't smart-cast properties of classes from another module: in `app/`, copy `entry.season` to a local `val` before checking it for null.
